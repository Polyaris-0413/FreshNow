# 一条记录多张照片 + 扫描页翻面收尾 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一条记录能存多张照片（最多 9 张、只给人看），并且扫描页翻面成「扫描 → 同一页收尾编辑」两态，把「补充信息」页与「保存后接着填」开关一并退休。

**Architecture:** 存储层把 `ScanRecord.imageName` 换成 `imageNames: List<String>`（Room TypeConverter + 重建表迁移），并保留一个派生的 `imageName`（= 第一张）让既有读取点不动——这样第一步落地时**行为完全不变**，现有测试全绿即证明。图片仍按内容散列命名，所以多图不引入引用计数：孤儿清理只是把「引用的名字集合」从单值换成并集。同步载荷两个字段并存（`imageName` 给旧版本、`imageNames` 给新版本），拉图从「按 syncId 取那一张」改成「按内容名取」。界面层把表单拆成可复用组件（`PhotoGrid` + `RecordEditForm(纯数据参数)`），编辑页与扫描页编辑态各持自己的草稿、共用同一套组件。

**Tech Stack:** Kotlin、Jetpack Compose（Material 3）、Room + KSP、Kotlinx Serialization、DataStore、Ktor client/server（局域网同步）、JUnit4（`app/src/test` 纯 JVM + `app/src/androidTest` 仪器化）。

**Spec:** `docs/superpowers/specs/2026-10-16-多图与扫描翻面-design.md`

## Global Constraints

- 设计语言 Material Design 3。尺寸、间距、圆角、颜色**只从** `ui/theme/`（`FreshNowSpacing`、`FreshNowSize`、`FreshNowShapes`、`MaterialTheme.colorScheme`）取，不得在界面里写死数值。
- 记录的一切写入必须经 `ScanRecordRepository`（它负责盖 `updatedAt` / `updatedBy`）；漏一处那次修改就永远同步不出去。
- 照片文件名保持**内容散列**（`ScanImageStore`：SHA-256 前 16 字节 + `.jpg`），不引入第二套命名、不引入引用计数字段。
- 改表结构必须补一条 `Migration` 并提交 KSP 导出的 `schemas/`；迁移测试用 `helper.runMigrationsAndValidate` 拿实体核对表结构。
- 注释只写代码表达不出的**为什么**，用中文；测试断言的消息也用中文，写清"守的是什么"。
- 上限 9 张只在界面层保证（`PhotoGrid` 与各加入路径）；数据层不设限，否则同步来的记录会存不进。
- 照片文件不在时，界面一律用占位图（`ic_no_image`），不崩、不阻塞。
- 实现完成后：`更新日志.txt` 记净更改、baseline profile 在虚拟机重录、真机编译安装并打开。

## Review Focus

这五类是 spec 没有明写、但会真的咬到用户的地方。每一条都已在下面某个任务的测试里钉住（括号里是那个任务）：

1. **策略/名字为空的照片名**（`""`、`"a/b.jpg"`、`"../../x.jpg"`）——对端或旧数据给的名字会进 `File(directory, name)`，必须当作"没有这张图"而不是拼出一个越界路径（Task 3）。

3. **同一张图被两条记录引用**（内容寻址下这是常态）——删掉一条不能删掉另一条还在用的文件（Task 2）。
4. **9 张的边界**（正好 9 张时「+」必须消失；加入路径不能造出第 10 张）（Task 4、Task 7）。
5. **旧版本设备发来的载荷**（只有 `imageName`、没有 `imageNames` 键）——必须能解出来并当成单元素列表，不能整条记录同步不过来（Task 3）。
