# 存放位置（位置）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 记录多出一个只有用户知道的「位置」字段，扫描保存后能直接接着填。

**Architecture:** 位置是记录的一个普通列，随记录一起落库、同步、备份。它不出现在扫描页（那一页只回执 AI 读到的东西），只在详情页显示、在编辑页填写。设置里加一个开关：打开时扫描页那颗按钮叫「下一步」，按下去先落库（沿用现有保存路径，照片一起写），再进这条记录的编辑页；关掉时与今天完全一样。

**Tech Stack:** Kotlin、Jetpack Compose（Material 3）、Room + Migration、DataStore、kotlinx.serialization。

**Spec:** 本次没有单独的设计稿，设计在与用户的对话中定稿；本文件开头这段就是规格，各任务「Interfaces」一栏是它的可执行形式。

## Review Focus

以下几条是规格暗示、但没有任何任务的测试会碰到的失败方式，按可能性排序。每条都已挂在相应任务的测试里。

1. **升级安装（v4 → v5）**：老用户的记录必须一条不少地活下来，位置读出来是空串；迁移写错在开发期看不出来（debug 允许破坏性迁移），只有发布后才炸。
2. **对端是老版本**：它发来的同步载荷里没有 `location` 字段，接收端不能抛异常，应当按空串收下。
3. **照片不能在「下一步」这条路上丢**：位置补填是加分项，照片没了是减分项——点「下一步」之后落库的记录必须已经有 `imageName`。
4. **开关关着时与今天完全一致**：不多一步、按钮文案不变、保存后照旧退出。
5. **位置空着时的显示**：详情页写「未填」而不是「未知」（「未知」在本应用的意思是"AI 没读到"），且扫描页根本不出现这一行。
